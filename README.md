# AINAZIK — сайт свадебного салона

Многостраничный сайт с каталогом платьев, карточками моделей, новостями салона, контактами и закрытой панелью управления.

## Запуск локально

Для локального запуска нужен Node.js 22 или новее.

```powershell
npm.cmd install
$env:SESSION_SECRET = "создайте-длинную-случайную-строку"
npm.cmd start
```

Откройте `http://localhost:3000`.

## Первый вход администратора

Создайте администратора из PowerShell. Используйте личный адрес и пароль длиной не менее 12 символов:

```powershell
$env:ADMIN_EMAIL = "email@example.com"
$env:ADMIN_PASSWORD = "ваш-длинный-пароль"
npm.cmd run setup:admin
Remove-Item Env:\ADMIN_EMAIL
Remove-Item Env:\ADMIN_PASSWORD
```

После запуска сайта откройте `http://localhost:3000/admin/`. Команда `setup:admin` создаёт учётную запись или обновляет пароль для указанного адреса; публичной регистрации в панели нет.

В панели можно добавлять, редактировать, публиковать и удалять платья и новости, отмечать новинки, загружать фотографии JPG/PNG/WebP размером до 8 МБ, а также обновлять адрес, телефон, WhatsApp, Instagram и часы работы.

В разделе «Тексты страниц» можно создавать, редактировать, скрывать и удалять дополнительные текстовые блоки для главной страницы, коллекции, новостей, раздела «О салоне» и контактов. У каждого блока могут быть заголовок, описание и порядок отображения. Текст выводится как обычный текст, а не исполняемый HTML.

## Публикация на VPS через Docker

В репозитории подготовлены `Dockerfile` и `compose.yaml`. Docker Compose запускает приложение и Caddy, который автоматически получает и обновляет TLS-сертификаты HTTPS. SQLite, загруженные фотографии и данные TLS сохраняются в Docker volumes.

Нужны Linux VPS с Docker Engine и Docker Compose plugin, домен и открытые снаружи порты TCP 80/443. Адрес сайта пока не выбран — вместо `ainazik.example` ниже укажите настоящий домен.

1. Создайте DNS-запись типа `A`, указывающую на публичный IPv4-адрес VPS. Добавьте `AAAA` только в том случае, если на VPS настроен доступный извне IPv6.
2. Подключитесь по SSH, установите Docker Engine и Compose plugin по официальной инструкции для вашей версии Linux, а затем клонируйте репозиторий на VPS.
3. В папке проекта создайте локальный `.env` из шаблона, установите домен и новый случайный секрет. Не добавляйте `.env` в Git и никому не отправляйте его содержимое:

   ```sh
   cp .env.production.example .env
   chmod 600 .env
   ```

   Откройте `.env` в редакторе и задайте `DOMAIN=ainazik.example` и `SESSION_SECRET` из команды `openssl rand -hex 48`.
4. Запустите сайт:

   ```sh
   docker compose up -d --build
   docker compose ps
   ```

5. Создайте администратора. Введите рабочую почту и пароль длиной не менее 12 символов в интерактивном SSH-терминале; после настройки удалите переменные из текущей оболочки:

   ```sh
   read -r -p "Admin email: " ADMIN_EMAIL
   read -r -s -p "Admin password: " ADMIN_PASSWORD
   echo
   docker compose run --rm --no-deps -e ADMIN_EMAIL -e ADMIN_PASSWORD app npm run setup:admin
   unset ADMIN_EMAIL ADMIN_PASSWORD
   ```

6. Проверьте `https://ваш-домен/`, затем откройте `https://ваш-домен/admin/`, добавьте реальные платья, фотографии, новости, тексты страниц и контакты.

Чтобы установить новую версию из Git, используйте `git pull` и `docker compose up -d --build`. Named volumes `ainazik-data`, `caddy-data` и `caddy-config` переживают пересборку приложения; не удаляйте их через `docker compose down -v`. Настройте и регулярно проверяйте резервное копирование базы и папки изображений в отдельное место.

На Windows эту конфигурацию можно предварительно проверить с установленным и запущенным Docker Desktop. Docker недоступен в текущей среде, поэтому здесь нельзя проверить сборку образа или выполнить публикацию на VPS. Для реального запуска потребуются адрес сервера (или выбранный хостинг) и домен, направленный на него.

## Бесплатный пробный запуск через Render и Supabase

Файл `render.yaml` содержит настройку бесплатного Render Web Service. Для постоянного каталога используется Supabase PostgreSQL, а для фотографий — публичная корзина Supabase Storage. При настройке данные проекта и секретный ключ Supabase передаются Render только как переменные окружения; `SUPABASE_SERVICE_ROLE_KEY` используется исключительно на сервере и не публикуется в браузере или Git.

1. Создайте бесплатный проект на [Supabase](https://supabase.com/dashboard). Выберите ближайший к Render регион.
2. В разделе **Storage** создайте публичную корзину `ainazik-images`. В ней будут храниться только фотографии каталога и публикаций.
3. В настройках подключения к базе скопируйте **Session pooler connection string** и подготовьте Project URL и секретный service-role ключ проекта. Не вставляйте секретный ключ ни в GitHub, ни в исходники.
4. Отправьте актуальный код в свой GitHub-репозиторий. На [Render](https://dashboard.render.com/) создайте **Blueprint** из этого репозитория и подтвердите создание сервиса из `render.yaml`.
5. При настройке задайте:
   - `DATABASE_URL` — Session pooler connection string Supabase;
   - `DATABASE_SSL_CA` — корневой SSL-сертификат Supabase из **Project Settings → Database → SSL Configuration → Download Certificate**, если соединение завершается ошибкой проверки сертификата; вставьте содержимое PEM целиком только в переменную Render;
   - `SUPABASE_URL` — Project URL;
   - `SUPABASE_SERVICE_ROLE_KEY` — service-role secret key;
   - `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD` — личную почту и временный пароль длиной не менее 12 символов, чтобы создать администратора при первой успешной загрузке приложения.
6. После успешного деплоя откройте сгенерированный адрес Render и `/admin/`, проверьте работу сайта и вход администратора. Затем сразу удалите `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD` из переменных Render и сохраните настройки. Удаление этих переменных не удаляет уже созданную учётную запись.

Сайт будет доступен на бесплатном адресе Render. Render Free засыпает после примерно 15 минут без обращений, файловая система у него временная, а бесплатный web service ограничен 750 часами в месяц; проект использует Supabase вместо локальных файлов, чтобы данные и загруженные фотографии не пропадали при перезапуске приложения. Бесплатный проект Supabase может приостановиться после недели бездействия; лимиты Free включают 500 МБ базы и 1 ГБ файлового хранилища. Поэтому это демонстрационный/пробный запуск, а не надёжный круглосуточный хостинг для действующего магазина. Условия тарифов могут меняться: [ограничения Render Free](https://render.com/docs/free), [тарифы Supabase](https://supabase.com/pricing).

Для полноценной работы магазина без засыпания приложения и приостановки базы используйте платный сервис с постоянным хранилищем или подготовленный выше VPS-вариант.

Для альтернативного хостинга переменные окружения перечислены в `.env.example`. Production-серверу необходимы `NODE_ENV=production`, постоянный `SESSION_SECRET` и HTTPS. В режиме SQLite нужны постоянные `DATA_DIR` и `UPLOAD_DIR`; в режиме Supabase постоянными должны быть внешняя база и Storage. Не запускайте несколько экземпляров локального SQLite-приложения без общей базы данных.

Каталог пустой при первой установке. Демонстрационные товары и вымышленные контакты посетителям не показываются.
